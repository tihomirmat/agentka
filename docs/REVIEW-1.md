## 6. Comparison with the reference screen (structure only)

- Matches: left sidebar; settings in the left column and the live widget on the right on Pregled; the one deploy action top right ("Namesti na spletno stran"); neutral greys, one accent, no gradients or illustrations.
- Differs: (1) the reference keeps the widget beside the settings for the whole screen; on Pregled the widget is sticky, but four stat cards sit above the two columns, so on a 900 px window the first view shows numbers and half a card, not "settings left, agent right". (2) Only Pregled and Termini have the right-hand live preview; Viri, Obvestila (has its own inline preview) and Nastavitve (where name, voice and greeting are edited) do not – editing the greeting in Nastavitve gives no preview at all. (3) The reference groups settings under tabs inside one screen; here the same agent is spread over Pregled (instructions), Nastavitve (name, voice, greeting, language) and Namestitev (colour, text input, position). A hairdresser looking for "what my agent says first" has three places to try.

## 7. What I could not check

- Voice: nothing speaks in stage 1; only the text widget was used.
- Real clipboard behaviour inside the preview host. I tested the success path in Chromium and the refused path by replacing `navigator.clipboard` (R8); I did not see the host itself.
- Native time inputs in other browsers. The AM/PM result (R4) is from headless Chromium with locale sl-SI; Firefox, Safari and iOS were not run.
- The customer's view of a failed payment, used-up minutes or a cancelled subscription. No sample login leads to such an account; I saw those states only from the admin side, and read the code of the strip and the notice (`AppShell.tsx:66-80`, `Subscription.tsx:30-80`) without seeing them rendered.
- Query error states ("Poskusi znova"): the sample api never fails, so none was seen.
- Keyboard-only use and screen readers: not tested. One observation only: on Termini a click on the radio found by role and name "Povpraševanje" timed out, a click on the visible card text worked (the real input is visually hidden under its label). Whether keyboard and screen reader work there was not verified.
- Widths other than 1440 and 400: only an overflow check and two screenshots at 768 and 1024 (R47, R61).
- Dark theme at 400 px: two screens only (Pregled, Rezervacije).
- File upload by drag and drop, long real content (very long business names, 200 pages), and behaviour with the real fonts served from the production font host (fonts were served locally as in `sweep.mjs`).
- Several of my own journey screenshots could not be opened because of an image limit in my session; for those states I relied on the page text captured by the same script run (listed as "measured").
